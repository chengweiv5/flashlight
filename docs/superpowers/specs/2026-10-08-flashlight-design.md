# Flashlight 第一版产品设计

- 日期：2026-10-08
- 目标设备：华为 Mate 60 Pro
- 目标系统：HarmonyOS 4.2.0 的 Android 兼容环境
- 定位：自用、简洁、实用的日常照明增强工具
- 状态：根据当前已确认的对话整理，等待书面设计审阅；尚未开始实现或真机验证

## 1. 背景与目标

用户希望在系统手电筒开关之外，获得更适合自用的照明体验。第一版不做多功能工具箱，围绕两种光源提供清晰、直接的操作。

核心目标：

1. 普通打开应用不误亮灯，需要照明时能够快速开启。
2. 明确区分后置 LED 照明与屏幕柔光照明。
3. 后置灯能够在熄屏后可靠使用，界面准确反映实际灯光状态。
4. 屏幕柔光可调亮度、可选白光或暖光，记住用户上次的设置。
5. 不提供用户明确不需要的延迟关灯、定时关闭功能。

本轮只记录产品范围与交互，不选择开发框架、依赖版本或后台服务方案，也不生成应用代码。

## 2. 两种光源

| 项目 | 手电筒 | 柔光灯 |
| --- | --- | --- |
| 发光位置 | 手机背面的 LED | 手机正面的屏幕 |
| 使用方式 | 背面对准要照亮的地方 | 屏幕朝向需要照亮的人或物 |
| 典型用途 | 找东西、照柜子内部、走夜路 | 床边照明、夜里起床、近距离补光 |
| 亮度调节 | 真机能力验证通过后才提供 | 通过应用窗口内的屏幕亮度调节 |
| 颜色选择 | 不承诺改变后置 LED 的颜色 | 白光、暖光 |
| 屏幕行为 | 目标是熄屏后仍可照明 | 屏幕本身是光源，使用时保持点亮 |

颜色切换只属于屏幕柔光，不把两种模式描述成同一盏灯的不同亮度档位。

## 3. 第一版范围

### 3.1 手电筒

- 点击大按钮开启或关闭后置 LED。
- 显示「已关闭」「照明中」等实际状态。
- 后置灯开启后，目标是锁屏、熄屏、切换应用时仍能照明。
- 后台照明时提供通知栏关闭入口，具体系统行为以目标设备实测为准。
- 在系统手电筒、相机和本 App 相互切换时，同步灯光实际状态。
- 灯光不可用时清楚提示，不显示虚假的「照明中」。
- 如真机支持可靠的多档 LED 亮度控制，再显示亮度档位；否则不显示调光控件。

### 3.2 屏幕柔光灯

- 支持白光、暖光两种颜色，第一版不做复杂彩灯。
- 提供亮度滑杆。
- 记住上次使用的颜色和亮度。
- 未开启时可以先调整颜色和亮度，不因此自动开启光源。
- 开启后以整个屏幕显示所选发光颜色。
- 底部提供亮度、颜色和关闭控件。
- 支持隐藏控件；轻点屏幕重新显示控件。
- 使用中保持屏幕点亮。
- 亮度调整仅作用于应用窗口；退出柔光模式或离开应用时恢复正常亮度行为，不修改系统全局亮度设置。

### 3.3 启动与快捷入口

- 普通打开 App 时不自动亮灯。
- 点击当前模式的大开关按钮后才开始照明。
- 提供独立的桌面「一键开灯」快捷入口，与普通启动入口区分。
- 快捷入口的具体命名及其光源选择规则，在实现前补充确认；本记录不将未讨论的默认规则视为已确认。

## 4. 首页与操作

### 4.1 模式入口

一个首页，顶部提供两个明确的模式按钮：

**手电筒｜柔光灯**

不拆分为两个 App，也不依赖左右滑动让用户猜测当前模式。

### 4.2 手电筒模式页面

- 深色背景。
- 中间为大开关按钮。
- 显示灯光的真实状态。
- 真机支持 LED 调光时才显示亮度档位。

### 4.3 柔光灯模式页面

关闭时：

- 保持深色界面。
- 显示白光／暖光选择、亮度设置和开启按钮。

开启时：

- 全屏显示所选颜色，使用所选亮度。
- 底部提供颜色、亮度和关闭控件。
- 控件隐藏后，轻点屏幕即可重新显示。
- 控件自动隐藏与否、等待时长和具体手势不在本次已确认范围内。

## 5. 光源切换与状态规则

### 5.1 基本规则

1. **灯关闭时切换模式，只选择光源，不自动亮灯。**
2. **灯开启时切换模式，切换到另一种光源。**
3. **默认一次只开启一种光源，不让背面灯与屏幕灯无意中同时开启。**
4. **普通重新打开 App 不自动恢复点亮状态。**
5. **记住柔光参数，不等于恢复亮灯。**

第 4 条指上次照明已经结束后的新启动；如果后置灯仍在后台照明，返回 App 必须如实显示「照明中」，不能为满足「普通启动不亮灯」而误关正在使用的灯。

### 5.2 交互状态表

| 当前状态 | 操作 | 预期结果 |
| --- | --- | --- |
| 手电筒已关闭 | 切换到柔光灯 | 后置灯与屏幕灯均不亮，显示柔光设置 |
| 柔光灯已关闭 | 切换到手电筒 | 两种光源均不亮，显示手电筒开关 |
| 手电筒已关闭 | 点击开启 | 请求开启后置灯，按实际结果显示状态 |
| 柔光灯已关闭 | 点击开启 | 屏幕按已选颜色和亮度发光 |
| 后置灯照明中 | 切换到柔光灯 | 关闭后置灯，再开启屏幕柔光 |
| 屏幕柔光照明中 | 切换到手电筒 | 结束屏幕柔光，再请求开启后置灯 |
| 任一模式照明中 | 点击关闭 | 结束当前光源照明，回到关闭态 |
| 后置灯照明中 | 系统或相机改变灯光状态 | 界面同步实际结果，不保留过时的点亮状态 |

切换到后置灯失败时，不能声称开启成功。错误提示样式、是否提供恢复上一光源按钮，留给实现设计决定；不静默引入自动重开灯行为。

## 6. 明确不做

### 6.1 用户明确排除

- 延迟关灯。
- 定时关闭。
- 上述功能对应的倒计时、时间档位和相关设置。

### 6.2 第一版不纳入

以下项目曾作为候选讨论，但未被选入当前第一版：

- SOS、爆闪、摩斯电码。
- 放大镜与相机补光。
- 指南针等无关工具。
- 复杂彩灯及暗红色等额外屏幕颜色。
- 摇一摇、全局音量键、悬浮球等扩展入口。
- 控制中心第三方快捷开关。
- 两种光源同时照明的独立模式。

第一版不做不代表未来永久排除；新增功能需要重新确认。

## 7. 体验与隐私原则

- 纯离线、无广告、无账号、无埋点。
- 只申请实际需要的权限。
- 普通界面采用深色主题，避免启动白屏。
- 开关操作直接，不设置广告页或妨碍开关的启动动画。
- 关灯后停止不必要的后台工作。
- 不以快速闪烁冒充 LED 亮度调节。
- 系统权限或资源限制必须明确提示，不以不可靠的绕过方式伪装正常工作。

这些内容是后续工作，不是已经完成的设备验证。

| 事项 | 验证或决策要求 | 对范围的影响 |
| --- | --- | --- |
| 目标设备当前系统能力 | 读取真机系统和 Android 接口级别，不仅依据 HarmonyOS 版本字符串推断 | 确定实际可用接口 |
| 后置 LED 调光 | 验证系统接口、硬件能力和实际调光效果 | 支持才做；不支持则隐藏相关控件 |

| 桌面快捷入口 | 验证目标桌面可用性，并确认其命名与开启光源规则 | 不把普通 App 启动改成自动亮灯 |
| 柔光控件细节 | 确认显示／隐藏方式及具体视觉参数 | 不改变轻点可重新显示控件的约定 |
| 开发方案 | 书面设计审阅后，再制定技术方案与实现计划 | 本次提交不构成开始写应用代码的授权 |
